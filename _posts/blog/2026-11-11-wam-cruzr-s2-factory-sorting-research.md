## 当前场景与条件

**场景与任务：** 工厂流水线分拣。机器人从流水线上拿起一个工件，将工件移到脸前扫码，再根据编码放到对应位置。调研目标是先跑通公开世界模型与视觉语言动作（VLA）项目，再评估其对抓取、扫码姿态调整和放置动作的帮助；扫码解码和编码到目标位置的映射先由独立模块完成。

**现有硬件：** 根据目前提供的规格资料，Cruzr S2 为轮式人形机器人，身高约 176 cm、重量约 188 kg；机身不含灵巧手共 22 个自由度，双臂各 7 个自由度，腰部 1 个、头部 2 个、轮式底盘 2 个。当前末端执行器确认为夹爪，不是灵巧手。7 自由度机械臂理论上足以控制末端的三维位置和姿态，夹爪更适合稳定夹取和搬运，不适合复杂的在手内旋转或精细重定位。

**仍需核实的接口：** 相机类型与安装位置、夹爪负载和控制方式、机械臂末端/关节控制权限、状态读取接口、控制频率、时间戳同步和 SDK 文档。GPU 型号、数量、显存及外部计算机接入条件也尚未确认。真机适配前需确认能同步获取图像、机器人状态与动作记录，并能发送所需控制指令。

**对当前任务的判断：** 这套硬件适合先固定底盘，仅使用单臂完成“抓取—移动到扫码位—放置”。第一版不建议同时学习底盘移动、全身姿态和机械臂精细操作；流水线任务的主要风险更可能来自夹爪抓取稳定性、视觉标定、定位精度、扫码视角和控制接口，而不是单臂自由度数量。

## DreamerV3

**主要框架：** 将图像和本体状态编码为潜在状态，由循环状态空间模型（RSSM）预测动作之后的状态、奖励和终止信号，再用“想象轨迹”训练 Actor-Critic 策略。执行时根据真实观测更新状态并由策略输出动作，标准方法不在每一步搜索候选动作。

**优点：** 世界模型和想象式控制链路清晰，适合学习基础原理；官方代码和环境较完整；对模型视频生成质量的依赖较低。

**缺点：** 通常需要自己定义环境、奖励和交互训练；直接迁移到 Cruzr S2 需要较多工程封装；不直接处理扫码语义，也不是面向机器人视频—动作联合生成的 WAM。

**复现难度：** 官方小任务入门中等，完整论文结果较难。适合学习“世界模型如何帮助策略学习”；迁移到 Cruzr S2 仍需定义观测、动作、奖励和环境接口。

**所需条件：** Python 3.11+、JAX 和任务环境，仓库提供 Docker。支持 CPU 调试，正式训练建议使用兼容 JAX 的 GPU，显存与耗时随模型、批量和任务变化。

**复现流程：** 安装依赖 → 选择 Crafter 等官方任务 → 用 debug 配置检查运行链路 → 切回正常配置训练 → 查看奖励曲线与预测结果，并重复评测。debug 跑通不代表策略已学会任务。

[论文（2023 预印本 / 2025 Nature）](https://arxiv.org/abs/2301.04104) · [作者维护的开源重实现与操作说明](https://github.com/danijar/dreamerv3)

## DreamZero

**主要框架：** 基于视频生成模型，在共享网络中联合生成未来视频与机器人动作块。执行后用真实观测刷新上下文，形成“观测 → 视频/动作联合预测 → 执行 → 再观测”的 WAM 闭环。

**优点：** 视频预测提供物理和时序先验；相比从零训练机器人策略，可能减少目标任务示范量；可围绕动作后果预测和异常恢复开展进一步研究。

**缺点：** 对多 GPU、显存、CUDA 版本、多相机输入和时间同步要求高；公开权重不直接支持 Cruzr S2，需要适配本体数据和动作空间；夹爪抓取、扫码和安全控制仍需独立保障；直接生成全身动作的工程风险较高。

**复现难度：** 官方推理较高，Cruzr S2 适配更高。官方权重不等于已支持 Cruzr S2，还需采集本体数据、适配观测与动作接口并进行微调。

**所需条件：** 公开的 14B 标准推理路线要求 Python 3.11、PyTorch 2.8+、CUDA 12.9+ 和至少两张 GPU。官方测试平台包括 H100、GB200，具体配置需按官方说明核对，不能假定任意两张消费级显卡都能运行。

**复现流程：** 安装依赖并下载 DreamZero-DROID 权重 → 启动多卡推理服务 → 运行测试客户端，确认动作返回和预测视频输出 → 完成 DROID 仿真闭环评测 → 采集 Cruzr S2 同步数据并适配、微调 → 从单阶段真机测试扩展到完整分拣。初次推理无需先下载训练数据；仿真中的托管 API 路线需申请访问，自建服务需核对客户端协议。

[论文（2026）](https://arxiv.org/abs/2602.15922) · [代码与复现说明](https://github.com/dreamzero0/dreamzero) · [新本体适配指南](https://github.com/dreamzero0/dreamzero/blob/main/docs/DATASET_TO_GEAR_AND_TRAIN.md)

## GR00T（N1.5 同平台适配路线）

**主要框架：** 由视觉语言主干理解图像与语言指令，再由结合机器人状态的 Diffusion Transformer 动作头生成连续动作块，接入机器人控制器执行。N1.5 使用流匹配与未来潜在表示对齐（FLARE）等训练目标，视觉语言主干在预训练和微调阶段保持冻结，属于视觉语言动作（VLA）策略。

**优点：** 利用真实机器人、合成轨迹和互联网视频预训练，支持新物体与新行为的泛化研究；官方提供基础权重、自有数据微调及新本体适配流程；已有 Cruzr S2 的公开适配记录，可参考其观测、动作和 SDK 接入方式，减少从零摸索接口的工作。

**缺点：** 通用模型的泛化能力不等于在 Cruzr S2 上无需适配。第三方同平台记录使用被动侧夹，20 维动作不含电动夹爪开合，不能直接用于当前夹爪配置；公开记录已包含准备姿态动作与真机 shadow 推理，但未证明 VLA 真机抓放成功或泛化效果。扫码、夹爪控制及动作执行仍需独立适配。

**复现难度：** 官方示例推理中等，Cruzr S2 闭环适配较高。同平台记录中的厂商专用模型包未随仓库公开，需确认是否能获取与当前末端执行器匹配的配置和权重；否则需采集自有示范，从基础模型微调。

**所需条件：** 本节按官方 `n1.5-release` 版本整理，推荐 Python 3.10、CUDA 12.4 和兼容 PyTorch 的 NVIDIA GPU；官方验证过 RTX 4090 等设备，但可训练模块、批量和显存需求须按配置核对。另需同步的图像、状态与动作示范、LeRobot 兼容数据，以及 Cruzr S2 关节和夹爪控制接口，不能照搬其他 GR00T 版本的依赖或动作定义。

**复现流程：** 固定 N1.5 代码版本并下载基础权重 → 跑通示例推理 → 核实厂商同平台模型包及夹爪兼容性 → 对齐相机、关节顺序、单位和夹爪动作，采集并转换示范数据 → 配置本体并微调 → 离线评估与 shadow 测试 → 单阶段低速真机验证 → 测试未参与训练的工件、位置、光照和布局，分别记录成功率。

[官方 N1.5 代码与复现说明](https://github.com/NVIDIA/Isaac-GR00T/tree/n1.5-release) · [基础权重](https://huggingface.co/nvidia/GR00T-N1.5-3B) · [Cruzr S2 第三方适配与验证记录][cruzr-groot-guide]

### 模型输入输出与 SDK 接口参考

**该专用权重的输入输出：** 单路 RGB 经配置处理为 `224×224`，配合语言指令和 20 维关节状态；每次输出 `10×20` 的动作块。20 维按“左臂 7、右臂 7、头部 2、升降机构 3、腰部 1”定义，任务为大箱子在低位或中位的抓取与放置。它不包含电动夹爪开合或底盘动作；20 维是该项目的策略定义，不是本机自由度统计，不能直接照搬到当前夹爪分拣任务。依据见[指南第 3 节][cruzr-groot-guide]。

| 接口或代码 | 第三方记录中的用途 | 对本项目的参考意义 |
| --- | --- | --- |
| `/sensor/camera/stereo/color/raw`，`shm_msgs/msg/Image2m` | 专用权重使用的 RGB 图像 | 核对图像编码、分辨率、时间戳及相机视角；当前机器人是否相同待核实 |
| `/mc/whole_joint_states`，`sensor_msgs/msg/JointState` | 按名称读取并重排关节状态 | 显式建立模型状态与本机关节的映射，不能只按数组位置读取 |
| `/mc/ft_states/L_hand_ft`、`/mc/ft_states/R_hand_ft`，`geometry_msgs/msg/WrenchStamped` | 左右腕力/力矩记录 | 可参考接触诊断与数据质量检查；原专用权重并未把力作为模型输入 |
| `/mc/sdk/robot_command`，`mc_task_msgs/msg/RobotCommand` | SDK 命令发送通道 | [公开 ROS 2 封装][cruzr-groot-backend]展示 `JointCmd` 的名称、模式、位置、速度等字段；实际支持范围需按本机 SDK 核实 |
| `/mc/motion_sdk/switch_to_vla`，`std_srvs/srv/Trigger` | 在该固件环境中切换至 VLA SDK 控制器 | [联调记录][cruzr-groot-status]表明“能发布消息、有订阅者”并不代表 SDK 控制器已接管；需核实当前控制器与服务返回状态 |

**对当前夹爪的适配判断：** 可优先借鉴相机读取、关节映射、数据配置和模型到控制器的连接方式。原包的被动侧夹策略不学习电动夹爪开合，需向厂商索取电动夹爪版本的数据配置和示例；若没有，应按[第三方指南第 13.5 节][cruzr-groot-guide]与[官方新本体微调流程][groot-new-embodiment]，定义包含夹爪状态与命令的数据配置，采集本机示范并从基础模型微调。

### 真机推理记录与已验证范围

以下均为第三方文档记录；准备姿态动作、shadow 通过和策略完成抓取是不同的验证环节。

| 时间与环节 | 公开记录 | 可以据此判断的范围 |
| --- | --- | --- |
| 2026-08-28，初期 shadow | 模型能返回动作块，但从不匹配的初始姿态出发，多次被首点跳变检查拒绝；未发送物理动作 | 推理链路可运行，初始姿态与动作连续性仍影响部署，不能以返回动作认定可执行 |
| 2026-09-14，准备姿态动作 | 作者记录 HOME→READY、READY→ENTRY 各 5 个阶段均返回成功，操作员确认结果 | 对应场景的准备动作已进行真机测试；这些动作不是 VLA 完成的抓取 |
| 2026-09-14，从 ENTRY 进行 shadow | 静止状态下收到 6 个动作块，6 个均通过该项目的 shadow 检查；检查运动变化的范围为 14 个手臂轴，其余 6 轴锁定 | 已有真实图像和状态下的策略推理与动作检查记录；未验证运动中的连续闭环，也不是 6 次抓取成功 |
| 同次 shadow 的计时 | 首次推理约 1.598 秒，后续 5 次推理中位数约 0.436 秒；完整后续迭代中位数约 0.479 秒 | 仅为该环境和配置的现场计时；模型输出多步动作，不能直接换算为关节控制频率，也不能承诺本机相同延迟 |
| 2026-09-14，物理执行联调 | 一次发送指令后因跟踪错误退出；修正控制器切换后，后续尝试在切换阶段超时，未发布动作帧 | 模型到物理控制的集成尚有未解决问题；截至该记录，仍无 VLA 成功抓箱、分拣或泛化评测证据 |

准备姿态与 shadow 数据见[实验记录][cruzr-groot-entry]，最新失败状态见[当日状态汇总][cruzr-groot-status]。该组记录最有复用价值的是接入流程、初始姿态约束和问题定位方式，不能将其作为 Cruzr S2 上已有成熟通用抓取策略的证明。

### 本项目采用方式与需向厂商确认的资料

**当前部署主线选择 GR00T。** 优先确认厂商是否有适配本机电动夹爪的模型包；匹配时参考其配置继续微调，不匹配时使用公开 N1.5 基础权重建立本机动作定义。先固定底盘、用单臂完成“抓取—移到扫码位—放置”，扫码使用独立解码模块，再逐步测试未参与训练的工件、位置、光照和布局。

向厂商确认以下资料后，再确定训练与真机执行配置：

- 电动夹爪版 Cruzr S2 的 `DataConfig`、关节顺序、单位、夹爪状态与命令定义，以及匹配的示范和权重；确认是否与 `cruzrss2_vla_pack-002` 属于不同配置。
- 本机固件匹配的相机/状态读取与动作发送示例、SDK 控制权限、控制器切换方式、可用频率和返回码含义。
- 该权重适用的相机视角、初始姿态、工作空间及已测试任务，是否有区分已见条件与未见条件的真机成功率记录。
